# rssradar — дизайн

**Дата:** 2026-07-21
**Статус:** дизайн согласован, готов к плану реализации

## Что это

Скилл для Claude Code «в раздачу»: мониторит тренды в нише через RSS-фиды.
Пользователь задаёт источники (вручную по URL или по теме — Claude находит фиды
сам), rssradar регулярно собирает свежие статьи, а Claude раз в неделю сводит их
в дайджест с выделением горячих тем. Между дайджестами — дешёвый «пульс»:
алерт, когда тема резко всплывает по объёму публикаций. Плюс разовая
визуальная карта трендов в браузере.

RSS-брат [instawatch](https://github.com/Natalyyyy/instawatch): та же архитектура
(`fetch` → SQLite → `report` → Telegram + `schedule`), но источник данных —
открытый и бесплатный.

## Позиционирование

Главная ценность для раздачи — **нулевая стоимость данных**. Никаких Apify
($8–10/мес), токенов Meta или их обновления раз в 60 дней. Единственный расход —
лимиты подписки Claude на недельный дайджест (пульс и сбор данных Claude не зовут).
Это делает rssradar гораздо более лёгким подарком, чем instawatch.

## Ключевые решения (согласованы при брейнсторме)

| Вопрос | Решение |
|--------|---------|
| Что такое «тренд» | **Гибрид**: дайджест всех новинок + Claude сверху выносит 2–3 горячие кросс-темы (упомянутые в нескольких источниках) |
| Что ловит пульс | **Всплеск объёма**: термин резко вырос над своей базовой линией И встречается в N+ разных фидах. Детекция без Claude |
| Морфология для пульса | **Лемматизация сразу** — pymorphy3 для RU («агентов»→«агент»), чтобы пульс не шумел с первого дня |
| Формат карты | **Визуальная HTML-карта**, самодостаточный файл, открывается в браузере локально (не claude.ai Artifact — чтобы работало у любого) |
| Источник данных | `feedparser` (RSS/Atom), без API |
| Подключение источников | Два режима: вручную по URL + по теме через exa-поиск |

## Архитектура

Зеркалит instawatch. Все команды — из папки скилла.

```
rssradar/
  fetch.py       — тянет фиды (feedparser), пишет в SQLite, дедуп по entry-id/ссылке
  report.py      — режимы: weekly | pulse | map
  schedule.py    — launchd (Mac) / cron (Linux); перенос из instawatch, rename меток
  telegram.py    — отправка ботом пользователя; перенос из instawatch как есть
  common.py      — конфиг, пути, подключение к БД, лемматизация
  discover.py    — поиск и валидация RSS-фидов (новый модуль)
  prompts/       — промпты для дайджеста и карты
  config.json    — фиды, окна, пороги, времена (по образцу config.example.json)
  .env           — TELEGRAM_TOKEN, TELEGRAM_CHAT_ID (секреты, не в git)
  SKILL.md       — онбординг и команды для Claude
  README.md      — установка для человека
  tests/         — pytest
```

### Хранилище (SQLite)

Таблица `entries`:

| Поле | Назначение |
|------|-----------|
| `feed_url` | из какого фида |
| `entry_id` | guid/id записи (или ссылка, если id нет) — ключ дедупа |
| `title` | заголовок |
| `link` | ссылка на статью (обязательна в каждой строке отчёта) |
| `published` | дата публикации из фида |
| `summary` | краткое описание/контент из фида (если есть) |
| `first_seen` | когда rssradar впервые увидел запись |

Таблица `term_counts` (для пульса): нормализованный термин × дата × число фидов,
где встретился. Считается инкрементально при каждом `fetch`.

Дедуп по `(feed_url, entry_id)` — статья не повторяется между прогонами.

## Модули

### fetch.py

- Читает `config.json` → список фидов.
- Для каждого: `feedparser.parse(url)`, берёт свежие записи, вставляет новые
  в `entries` (INSERT OR IGNORE по ключу дедупа).
- Обновляет `term_counts`: лемматизирует заголовки новых записей (pymorphy3 для
  кириллицы, lowercase+стоп-слова для латиницы), инкрементит счётчики термин×дата
  с учётом числа разных фидов.
- Флаги: `--limit N` (холодный старт), без флага — обычный догон.
- Печатает: сколько новых записей, какие фиды недоступны.

### discover.py

Два режима, вызывается из онбординга:

1. **По URL сайта** — качает главную, ищет `<link rel="alternate"
   type="application/rss+xml">`; если нет — пробует типовые пути `/feed`,
   `/rss`, `/atom.xml`, `/feed.xml`, `/index.xml`. Валидирует через feedparser.
2. **По теме** — Claude (в SKILL-флоу) зовёт exa (`exa-core:search`) по теме,
   получает кандидатов-сайтов, прогоняет каждый через режим 1, отдаёт выверенный
   список фидов. Пользователь подтверждает, что уходит в `config.json`.

Возвращает нормализованные валидные URL фидов; невалидные — с причиной.

### report.py

Три подкоманды, все умеют `--send` (в Telegram) и по умолчанию печатают в чат.

- **`weekly`** (гибрид, headless Claude): берёт записи с `first_seen` за неделю,
  формирует контекст, промптом просит Claude сгруппировать по темам, вынести
  2–3 горячие кросс-темы наверх, ниже — остальное списком. Ссылка в каждой строке.
  Если вызов Claude не сработал — шлёт метрики без выжимки (как instawatch).
- **`pulse`** (без Claude): по `term_counts` находит термины, где счётчик за
  короткое окно резко превысил базовую линию И покрытие ≥ N фидов. Формирует
  короткий алерт «набирает обороты: X (в M источниках)» + топ-ссылки по термину.
  Claude максимум формулирует одну фразу (опционально), детекция — чистый Python.
- **`map`** (разово, визуально): собирает кластеры тем (той же логикой, что
  weekly — через Claude), рендерит самодостаточный HTML (кластеры, размер =
  горячность), пишет в `data/map-YYYY-MM-DD.html` и открывает в браузере
  (`open`/`xdg-open`). Вид карты дорабатывается отдельно (пара макетов на согласование).

### telegram.py / schedule.py / common.py

- `telegram.py` — перенос из instawatch без изменений (split_message + send).
- `schedule.py` — перенос, замена меток `com.instawatch.*` → `com.rssradar.*`,
  `CRON_MARK` → `# rssradar`. Ставит два задания: weekly (день+время) и pulse (время).
- `common.py` — пути, load_config, подключение к SQLite, функция нормализации/
  лемматизации термина (общая для fetch и pulse).

## config.json (пример)

```json
{
  "feeds": ["https://example.com/feed", "https://blog.example.org/rss"],
  "pulse_min_feeds": 2,
  "pulse_spike_multiplier": 2.0,
  "pulse_baseline_days": 14,
  "pulse_window_days": 2,
  "weekly_window_days": 7,
  "fetch_limit_cold": 30,
  "weekly_day": "sun",
  "weekly_time": "18:00",
  "pulse_time": "10:00"
}
```

## Онбординг (первый запуск: нет config.json или .env)

Мастер в SKILL.md, по одному вопросу за раз, на русском:

1. **Python 3.9+** и зависимости (`feedparser`, `requests`, `pymorphy3`).
2. **Источники** — вручную по URL или по теме (exa). discover.py валидирует,
   показывает список, пользователь подтверждает.
3. **Telegram** — бот через @BotFather, chat_id через getUpdates (как instawatch).
4. **Холодный старт** — `python3 fetch.py --limit 30`, показать статистику.
5. **Режим** — неделя / пульс / оба / только вручную. Для автоматики —
   `python3 schedule.py install` (предупредить, что weekly тратит лимиты Claude).

## Команды после настройки

- «трендwatch по RSS» / «сделай дайджест» → `report.py weekly`
- «проверь пульс» → `report.py pulse`
- «покажи карту трендов» → `report.py map`
- «добавь фид X» / «найди фиды по теме Y» → discover.py → config.json → холодный сбор
- «убери фид X» → удалить из config.json
- «выключи/включи автоматику» → `schedule.py remove` / `install`
- «как там мониторинг» → `schedule.py status`

## Границы (YAGNI)

- Не парсим полные тексты статей по ссылкам — работаем с тем, что отдаёт фид
  (title + summary). Достаточно для тем и пульса.
- Пульс — только частотный сигнал, без семантики. Семантику даёт weekly-дайджест.
- Карта — статичный HTML, без интерактива/бэкенда.
- Латинские фиды — без лемматизации (lowercase + стоп-слова); лемматизация RU-only.

## Дисклеймер (для README)

Мониторим только публичные RSS-фиды, которые сайты отдают сами. Никакого
скрейпинга закрытого контента. Скилл не аффилирован ни с одним источником.
